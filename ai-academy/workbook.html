Part I · Learn the ideas by doing

Read one card, run its experiment, then explain the idea aloud in your own words. These are summaries and prompts for practice, not replacements for checking primary sources.

Lesson 01

01 · AI is a toolbox, not magic

A supermarket has shelf rules (traditional software), a cashier who learns demand patterns (machine learning), and an illustrator creating new flyers (generative AI). AI is the broad umbrella; machine learning fits within it.

Try it

Experiment: ask ChatGPT to classify five fictional customer reviews, explain why it chose each category, then invent a sixth borderline review. Manually score at least one misclassification.

Mini challenge · Challenge: explain the difference between an AI model and an AI product. ChatGPT is an application that may combine models with memory, search, tools and interfaces.

Lesson 02

02 · What a model actually learns

Weights are numbers adjusted during training, not drawers containing individual facts. A parameter is a learned numerical setting. Millions or billions of these values shape patterns. A GPU performs many math operations simultaneously, which helps training and inference.

Try it

Experiment: write 'The cat sat on the ___'. List three likely next words and explain how the preceding words influence your prediction. That's an analogy for token prediction, not a literal model implementation.

Mini challenge · Challenge: explain why a highly confident response can still be wrong and why retrieval or a calculator may improve it.

Lesson 03

03 · Tokens, context and answers

Text is split into tokens—sometimes whole words, sometimes pieces. The model processes context, predicts the next token, appends it, and repeats. A separate search tool can fetch current evidence. A model without retrieval may have out-of-date information.

Try it

Experiment: ask the same question three ways: vague, detailed and with examples. Compare factual completeness, structure and actionable next steps.

Mini challenge · Challenge: identify whether each answer came from model generation, a retrieved source or an explicit computation.

Lesson 04

04 · Better prompts, better outcomes

Use GOAL + CONTEXT + CONSTRAINTS + OUTPUT + VERIFY. Example: 'Explain compound interest to a teenager, using ₹1,000 and 5% annual interest; show assumptions and an illustrative table.'

Try it

Experiment: ask Claude and ChatGPT to create a packing list for a two-day trip. Provide season, transport and luggage limit on the second attempt; score completeness.

Mini challenge · Challenge: turn a poor prompt into a reusable template.

Lesson 05

05 · Image production

A good image prompt describes subject, scene, composition, camera viewpoint, lighting, mood, colors, aspect ratio and what must not appear. Models may fail at exact logos, small text and object counts.

Try it

Experiment: design a fictional café poster with three different art directions. Compare typography and product consistency; fix issues by editing rather than regenerating randomly.

Mini challenge · Challenge: keep a short prompt log so you know what changed between versions.

Lesson 06

06 · Video, speech and slides

Begin with script → storyboard → generate clips → review continuity → record voice → add captions → assemble. For slides, start from a narrative rather than visual effects.

Try it

Experiment: create 5 slides teaching a friend what a GPU is. Make a 45-second narration, then verify the voiceover matches your slides.

Mini challenge · Challenge: spot one generated clip that distorts physics or changes the subject between shots.

Lesson 07

07 · AI in everyday life

AI helps convert unstructured notes into action items, generate meal plans from constraints, compare travel options, and simplify complicated letters. It should not quietly decide matters involving finances, privacy or health.

Try it

Experiment: take a fictional week's tasks, estimate time manually, then let an AI prioritize them. Compare your final schedule with reality.

Mini challenge · Challenge: measure minutes saved, not just how impressive the answer looks.

Lesson 08

08 · Finance, trading and commerce

Use AI for categorization, formulas, scenario models and reporting. Trading ideas need historical testing, transaction costs, survivorship-bias checks, risk limits and skeptical validation; a fluent model does not predict markets reliably.

Try it

Experiment: analyze five fictional transactions and manually verify totals. On synthetic price data, compare a simple moving-average strategy against buy-and-hold while accounting for fees.

Mini challenge · Challenge: flag any recommendation that promises guaranteed returns.

Lesson 09

09 · Manufacturing, design and literature

Manufacturing: classify defects, summarize maintenance logs, predict potential downtime only when enough quality data exists. Design: iterate concepts, requirements and usability tests. Literature: brainstorm characters, analyze structure and edit with author review.

Try it

Experiment: transform an invented factory defect log into a Pareto summary, then sketch two packaging designs and improve a 150-word story opening.

Mini challenge · Challenge: verify the generated defect counts and decide which creative changes preserve your voice.

Lesson 10

10 · Agents vs automations

Automation follows a predefined trigger and steps; an agent may evaluate results and choose next tools. More autonomy means more opportunities for error. Approvals, permissions and logging keep systems governable.

Try it

Experiment: draw an 'inbox triage' diagram: new message → classify → draft → human approve → send. Mark which steps require a person.

Mini challenge · Challenge: explain why a prompt-only assistant does not autonomously access Gmail.

Lesson 11

11 · Build no-code agents

Begin in n8n or Make with a manual trigger, input values, AI generation step and a preview-only output. Add connections after testing. Prefer least-privilege credentials and explicit confirmation for sends or edits.

Try it

Experiment: create the Morning Compass workflow with a manual trigger and sample tasks. Validate empty inputs, duplicate tasks, deadlines in the past and unsupported assumptions.

Mini challenge · Challenge: make a test checklist with expected outputs.

Lesson 12

12 · Nine agents, version one

Plan, inbox, money, research, meeting, creator, shopping, quiz and maintenance. Prototype in chat first, then one by one turn them into tool-enabled workflows using a verified data source and clear approvals.

Try it

Experiment: copy an agent prompt from the main site, fill in placeholders, run three test cases and record when it fails.

Mini challenge · Challenge: describe what would need to change before it runs on a real schedule.

Lesson 13

13 · Vibe coding for humans

HTML is page structure, CSS is styling, JavaScript powers behavior. Vibe coding asks an AI to help produce these, but you still specify what should happen and inspect code for mistakes.

Try it

Experiment: ask AI for a grocery checklist webpage with local-only saving, responsive layout, accessible buttons and no external library. Open the result and test offline.

Mini challenge · Challenge: ask AI to explain each file and its security implications.

Lesson 14

14 · Publishing and protecting

A static site can go live through GitHub Pages without a server. A public repository exposes its code. Never paste private API keys into client-side JavaScript. For private integrations, use a backend with authentication, authorization and usage limits.

Try it

Experiment: test navigation by keyboard and on a 360px screen; verify internal links, screenshot mobile overflow, open the live URL in a private browser session.

Mini challenge · Challenge: complete your release checklist before sharing.

Part II · Nine agent labs

Each lab starts as a manual, low-risk prototype. Sample inputs are intentionally fictional. Add external actions only with least-privilege permissions and explicit approval.

Morning Compass

Workflow: Manual trigger → sample task list → AI planning node → structured plan → display-only output.

Try this: Sample input: 'Pay electricity bill by 5 PM; buy groceries; walk 30 min; meeting 2–3 PM.'

Acceptance test

Check no appointment overlaps, realistic durations, and no new tasks invented.

Inbox Tamer

Money Mirror

Build your first workflow with a visual editor

  1. Choose n8n or Make. Create a new scenario/workflow.
  2. Add a manual trigger so nothing runs unattended.
  3. Add a sample input as text or structured fields. For Morning Compass, use a fictional to-do list.
  4. Add an AI/model step with the agent's instructions from the academy homepage. Credentials may be required by your chosen provider.
  5. Require structured output: task, priority, time estimate, unresolved assumptions.
  6. Display the result for human review. Do not connect send/delete/purchase actions yet.
  7. Run three test cases: normal inputs, missing fields, and a malicious instruction hidden in retrieved text.
  8. Only after tests pass, add a scheduled trigger and narrowly scoped read-only connector. Add human approval before write operations.

Your first real program — a safe, local rule-based agent skeleton

This Python demonstration does not use a paid API or make outside changes. It teaches the agent loop of observe, choose, act and report.

tasks = [
    {"name": "Pay electricity bill", "urgent": True},
    {"name": "Read a chapter", "urgent": False},
    {"name": "Prepare meeting notes", "urgent": True},
]

def observe(items):
    return [x for x in items if x.get("name")]

def decide(items):
    return sorted(items, key=lambda x: not x.get("urgent", False))

def act(items):
    # Safe action: only produce text; never send or modify anything.
    return [f"{i+1}. {x['name']}" for i, x in enumerate(items)]

result = act(decide(observe(tasks)))
print("\n".join(result))

Once this makes sense, use the official OpenAI Agents SDK quickstart to replace the decision step with a real model. Keep API credentials on a server or in private environment variables, never in public GitHub Pages.

How to evaluate every agent

  1. Correctness: Are factual claims and calculations right?
  2. Grounding: Do sources exist and support the claims?
  3. Permissions: Could it change anything without approval?
  4. Privacy: Does it need all the information being provided?
  5. Reliability: What happens with no data, timeouts or contradictory instructions?
  6. Value: Did it save time, reduce mistakes or make a decision clearer?

Part III · Your launch and security checklist

  • All navigation and internal links point to existing files.
  • No hard-coded credentials, private keys or personal data in public HTML or JavaScript.
  • User-provided or model-generated text is displayed safely, never blindly executed as code.
  • External text is treated as untrusted data; instructions embedded in a web page must not override the user's goal.
  • Agent writes, sending messages, purchasing and deletion always require explicit approval.
  • Check mobile at 360px, desktop, keyboard tab order, contrast and clear error messages.
  • Test in two browsers and a private window after publishing.
  • Use GitHub Pages only for a static frontend. Use a properly secured backend for private integrations.
  • Have a rollback plan: previous Git commit and release notes.
